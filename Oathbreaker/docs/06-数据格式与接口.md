### 6.3 武器 DataMap 示例

data/oathbreaker/data_maps/item/weapon_profile.json

```json
{
  "values": {
    "spartanweaponry:longbow": {
      "category": "ranged",
      "damage": [
        { "type": "physical", "ratio": 1.0 }
      ],
      "required_classes": ["oathbreaker:ranger"],
      "ranged_scale": 1.0
    },
    "#oathbreaker:weapon_heavy": {
      "category": "heavy_melee",
      "damage": [
        { "type": "physical", "ratio": 1.0 }
      ],
      "required_classes": ["oathbreaker:warrior"],
      "ranged_scale": 0.0
    }
  }
}
```

魔神不参与武器适配；weapon_profile 不再包含 patron 字段。

> `required_classes` / `class_tags` 必须是完整 `ResourceLocation`（如 `oathbreaker:ranger`）；裸写 `ranger` 会被解析成 `minecraft:ranger`。
> `damage` 是数组，每项 `type` 取 `physical` / `magic` / `true`，`ratio` 会合并同类并归一化到 1.0；缺省为 100% 物理。一个武器可以同时有多段，例如 70% 物理 + 30% 魔法。

### 6.7 怪物锚点方块实体数据

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| EntityNbt | CompoundTag | 完整实体 NBT |
| SpawnChance | float | 默认 0.5 |
| FallbackEntityType | String（可选） | 兜底实体 ID |
| AnchorId | String（可选） | 调试标识 |

```java
public class MonsterAnchorBlockEntity extends BlockEntity {
    private CompoundTag entityNbt = new CompoundTag();
    private float spawnChance = 0.5f;
    private String fallbackEntityType = "";

    @Override
    protected void saveAdditional(ValueOutput output) {
        super.saveAdditional(output);
        output.store("EntityNbt", CompoundTag.CODEC, entityNbt);
        output.putFloat("SpawnChance", spawnChance);
        output.putString("FallbackEntityType", fallbackEntityType);
    }

    @Override
    protected void loadAdditional(ValueInput input) {
        super.loadAdditional(input);
        input.read("EntityNbt", CompoundTag.CODEC).ifPresent(tag -> entityNbt = tag);
        spawnChance = input.getFloatOr("SpawnChance", 0.5f);
        fallbackEntityType = input.getStringOr("FallbackEntityType", "");
    }
}
```

### 6.11 记忆残片

物品：oathbreaker:lore_fragment

DataComponent：fragment_index（1–5）

账户层记录 unlockedLoreFragments；Boss 死亡时对未拥有该残片的实例成员发放。

残片文本可放数据包 data/oathbreaker/oathbreaker/lore/fragment_1.json，客户端只读展示。

已解锁残片可在大厅图鉴重读；物品丢弃不影响账户解锁。

### 6.12 武器池与命中效果

JSON 路径：`data/<namespace>/oathbreaker/weapons/<name>.json`，文件路径即池条目 ID（如 `bow.json` → `oathbreaker:bow`）。

JSON 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `item` | ResourceLocation | 二选一 | 匹配单个物品 |
| `tag` | ResourceLocation | 二选一 | 匹配物品 Tag（`#` 不写） |
| `weight` | int | 否 | 抽取权重，默认 10；≤0 不参与抽取 |
| `pool_tags` | string[] | 否 | 池标签，用于筛选/抽取 |

```json
{
  "item": "minecraft:bow",
  "weight": 10,
  "pool_tags": ["ranged", "starter"]
}
```

JSON **不包含** `damage` / `profile` / 命中效果，因此不会修改武器原有伤害或行为；伤害仍由 DataMap `weapon_profile` 提供。

代码注册（可覆盖 profile 与命中效果）：

```java
WeaponPool.register(WeaponDefinition.builder(Oathbreaker.id("my_blade"))
        .item(ResourceLocation.fromNamespaceAndPath("my_mod", "blade"))
        .profile(profile)
        .hitEffect(effect)
        .build());
```

命中效果接口：

```java
public interface HitEffect {
    void onHit(HitContext context);
    default void onKill(HitContext context) {}
}
```

`HitContext` 包含：`attacker`、`target`、`weapon`、`weaponDefinition`、`damageProfile`、`damageDealt`、`source`、`hitSource`。技能系统接入后复用同一接口，`hitSource` 标为 `SKILL`。

解析优先级：代码注册 > JSON 池条目 > DataMap。`/oathbreaker pool` 查看池条目数，`/oathbreaker profile` 查看手持武器的池 ID、伤害构成与效果类名。
