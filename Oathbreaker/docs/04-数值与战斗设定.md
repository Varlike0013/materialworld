# 4. 数值与战斗设定

> 文档索引：[README.md](README.md) ｜ 完整原文：[Oathbreaker.md](Oathbreaker.md)

### 4.1 玩家属性（LoL 风格）

玩家面板对齐 LoL 的属性类型，但**数值尺度仍沿用 Minecraft**（20 点生命），不照搬 600 血/60 AD。当前默认把玩家最大生命与 AD 放大 5 倍、怪物生命放大 5 倍（`base_stats` / `mob_scaling` 配置），目的是先放大数值区间，方便后续细调。基础面板：护甲基础值在公式中按“原版护甲 + baseArmor”计算（原版 armor 属性上限 30，直接加修饰符会让装备被截断）；魔抗、法力、回复用固定 ID 永久修饰符，在登录/重生时施加。

| 属性 | 属性 ID | 来源 | 说明 |
|---|---|---|---|
| 攻击力 AD | `minecraft:generic.attack_damage` | 原版 | 近战/远程普攻、物理武器；默认 ×5 |
| 法术强度 AP | `oathbreaker:generic.ability_power` | 本 Mod | 技能与法术武器 |
| 生命值 | `minecraft:generic.max_health` | 原版 | HUD 显示实际值；默认 ×5 |
| 护甲 | `minecraft:generic.armor` | 原版 | 基础 30 + 装备护甲；物理减伤 |
| 魔法抗性 | `oathbreaker:generic.magic_resist` | 本 Mod | 基础 30；魔法减伤 |
| 暴击率 | `oathbreaker:generic.crit_chance` | 本 Mod | 0–1 |
| 暴击伤害 | `oathbreaker:generic.crit_damage` | 本 Mod | 默认 1.75（175%） |
| 护甲穿透（固定） | `oathbreaker:generic.armor_penetration` | 本 Mod | 先百分比后固定 |
| 护甲穿透（百分比） | `oathbreaker:generic.armor_penetration_percent` | 本 Mod | 0–1 |
| 法术穿透（固定） | `oathbreaker:generic.magic_penetration` | 本 Mod | 先百分比后固定 |
| 法术穿透（百分比） | `oathbreaker:generic.magic_penetration_percent` | 本 Mod | 0–1 |
| 技能急速 | `oathbreaker:generic.ability_haste` | 本 Mod | 冷却缩减 = AH / (100 + AH) |
| 生命回复 | `oathbreaker:generic.health_regeneration` | 本 Mod | 每 5 秒 |
| 法力回复 | `oathbreaker:generic.mana_regeneration` | 本 Mod | 每 5 秒 |
| 最大法力 | `oathbreaker:generic.max_mana` | 本 Mod | HUD 法力条 |
| 生命偷取 | `oathbreaker:generic.lifesteal` | 本 Mod | 仅物理普攻 |
| 全能吸血 | `oathbreaker:generic.omnivamp` | 本 Mod | 所有伤害类型 |
| 攻击速度 | `minecraft:generic.attack_speed` | 原版 | HUD 做 MC→LoL 展示换算 |
| 移动速度 | `minecraft:generic.movement_speed` | 原版 | 暂不在 HUD 展示 |

说明：

- 设计文档早期的 `ranged_damage` 属性仍保留，但 P2 的面板值统一走 AD（物理）与 AP（法术），不再用它做面板值。
- 基础面板：护甲 +30、魔抗 +30、最大法力 +300、法力回复 +15/5s、生命回复 +5/5s，可在 `base_stats` 分组调整。
- 生命/攻击倍率用 `ADD_MULTIPLIED_TOTAL` 固定 ID 修饰符，作用于最终总值（含武器伤害）；默认 5.0，可在 `base_stats.healthMultiplier` / `attackMultiplier` 调整。
- 生命、护甲、攻速、移速继续读原版 `minecraft:generic.*`，方便第三方装备与 Buff 直接叠加。

### 4.2 加成来源统一汇入 Attribute

| 来源 | 施加方式 |
| --- | --- |
| 技能/天赋 | AttributeInstance.addTransientModifier()，固定 ResourceLocation ID 便于移除 |
| 契约天赋永久加成 | 固定 ResourceLocation ID Modifier，登录/重生时施加 |
| 装备 | ItemAttributeModifierEvent 注入 |
| 药水/Buff | MobEffect.addAttributeModifier() 或同一事件钩子 |
| 第三方 Buff | 修改标准 Attribute 自动合并 |

禁止在 UI 或伤害代码中遍历技能/契约列表手动累加。

### 4.3 伤害管线（LoL 公式）

实现位置：`CombatDamageHandler`，监听 `LivingDamageEvent.Pre`（NORMAL），用 `getOriginalDamage()` 的护甲前原始伤害重新计算最终值：

```text
物理：raw × 100 / (100 + 有效护甲)
魔法：raw × 100 / (100 + 有效魔抗)
真实：raw
有效抗性 = max(0, 抗性 × (1 - 百分比穿透) - 固定穿透)
负抗性：raw × (2 - 100 / (100 - 抗性))
```

伤害分类：

- 玩家造成伤害：读 `weapon_profile.damage` 数组，可同时包含多段物理/魔法/真实；比例在 `DamageProfile` 中合并同类并归一化到 1.0。
- 玩家受到伤害：按伤害类型 Tag（`#oathbreaker:physical` / `#oathbreaker:magic` / `#oathbreaker:true`）分类；未标记的环境伤害继续走原版。
- 暴击：一次命中只判定一次；仅物理段享受暴击倍率，魔法/真实段不受影响。
- 吸血：生命偷取按物理段占比计算，全能吸血作用于全部类型。

示例：70% 物理 + 30% 魔法

```json
"damage": [
  { "type": "physical", "ratio": 0.7 },
  { "type": "magic", "ratio": 0.3 }
]
```

顺序与优先级：

1. `CombatDamageHandler`（NORMAL）拆分伤害段、判定暴击、逐段应用穿透与抗性。
2. `ClassWeaponHandler`（LOWEST）做职业武器裁决；不匹配时强制 `setNewDamage(1.0F)`，覆盖上一步。
3. `LivingDamageEvent.Post` 结算吸血，并触发武器的命中效果接口。

已知边界：

- 用 `getOriginalDamage()` 重算意味着原版护甲公式与保护附魔不再参与减法；这是“LoL 公式接管”的预期结果。
- 原版跳跃暴击会先乘 1.5 倍进入 `originalDamage`，再叠加本 Mod 暴击率，存在双重暴击的可能；P3 可用 Mixin 关闭原版暴击。
- 玩家护甲有 +30 基础值；怪物暂用原版护甲数值（通常 2–10），魔抗默认 0，等 P3 的 `MobProfile` 缩放补齐。
- UI 面板值只显示攻击方 AD/AP，不含目标抗性；实际伤害在事件中按上述公式计算。
- 魔法/真实技能按伤害类型 Tag 单独成段；物理技能目前会沿用主手武器 profile，技能系统接入时应改用独立伤害源或后续的伤害构成 registry。

### 4.4 重生边界

技能施加的 Transient Modifier 死亡重生后需重新施加。

PlayerEvent.Clone 复制持久数据；重生/登录后重建 Modifier。

永久性局外加成（契约天赋、永久属性点、魔抗/法力基础面板、生命/攻击倍率）用固定 ResourceLocation ID Modifier，登录/重生时统一施加/移除；生命倍率变化后登录/重生补满生命。

> 1.21.1 起 `AttributeModifier` 的唯一 ID 已从 UUID 改为 `ResourceLocation`，本文原“固定 UUID”表述统一按“固定 ID”实现。

### 4.5 武器属性覆盖

第三方武器伤害、攻速、耐久等常规属性优先通过 Attribute Modify / DataGear 数据驱动覆盖。

本 Mod 不写每个武器适配器；只维护分类 Tag/DataMap、职业适配与技能加成逻辑。

修改攻速注意自定义 id 与固定 id 的叠加语义差异。

/reload 后服务端重算并推送 WeaponInfoPayload。

### 4.6 怪物缩放（锚点物化时）

| 属性 | 缩放策略 | 说明 |
| --- | --- | --- |
| 生命值 | 强缩放：玩家数量为主，levelIndex 基础增长 | 例：1 + 0.5*(playerCount-1) + 0.15*levelIndex |
| 攻击力 | 弱缩放：levelIndex 为主，玩家数量小乘区 | 例：1 + 0.2*(playerCount-1) + 0.25*levelIndex |
| 护甲/韧性 | 仅精英与 Boss 少量缩放 | 普通杂兵不缩放护甲 |
| 移速/攻速 | 默认不缩放 | 特殊词缀单独处理 |

固定 ID AttributeModifier；生成后 setHealth(getMaxHealth())。

全局生命倍率：`mob_scaling.healthMultiplier` 默认 `5.0`，由 `MobHealthScaling` 在 `EntityJoinLevelEvent` 对所有 `Enemy` 应用 `ADD_MULTIPLIED_TOTAL`，并按当前血量比例恢复；已带该固定 ID 的怪物不重复缩放。该倍率只放大生命区间，方便后续调参；攻击力缩放仍按上表/`MobProfile` 处理。

具体曲线由 mob_profile DataMap 指定。

### 4.7 职业武器适配

```java
@SubscribeEvent(priority = EventPriority.LOWEST)
public static void onLivingDamagePre(LivingDamageEvent.Pre event) {
    if (!(event.getEntity() instanceof Monster)) return;
    if (!(event.getSource().getEntity() instanceof ServerPlayer player)) return;
    if (!event.getSource().is(ModTags.DamageTypes.PHYSICAL)) return;

    ItemStack weapon = player.getMainHandItem();
    WeaponProfile profile = WeaponPool.resolveProfile(weapon);
    if (profile == null) return; // 无分类武器不受限

    if (!profile.isUsableBy(player)) {
        event.setNewDamage(1.0F);
    }
}
```

判定依据：玩家当前职业标签 vs weapon_profile.required_classes / class_tags。

魔神不参与此判定。

无 weapon_profile 的空手、方块、第三方未标记武器不受惩罚。

`setNewDamage(1.0F)` 在 LOWEST 优先级执行，覆盖此前所有乘区（包括 LoL 抗性公式）。

### 4.8 死魂灵与契约加成

死魂灵获取公式：soulPerPlayer = baseSoul * (1 + 0.15 * levelIndex)。

每人相同，不受玩家数量影响；Boss 为实例全体成员，普通怪物为造成过伤害的玩家。

契约天赋加成走固定 ResourceLocation ID AttributeModifier，登录/重生施加；切换天赋时移除旧 ID、施加新 ID。

契约等级只决定技能池可见范围与天赋层数，不直接线性加属性；属性来自所选天赋。

每层天赋 2–3 选 1，可大厅切换；切换不消耗死魂灵，但不可在战斗中切换。

### 4.9 命中效果与武器池

命中效果接口（武器与技能共用）：

```java
public interface HitEffect {
    void onHit(HitContext context);
    default void onKill(HitContext context) {}
}
```

`HitContext` 提供：攻击者、目标、武器 `ItemStack`、武器池定义、伤害构成、实际伤害、伤害来源、来源类型（WEAPON/SKILL）。回调在服务端主线程、伤害应用后触发。

两种接入方式：

| 方式 | 位置 | 是否修改武器效果 |
|---|---|---|
| JSON 武器池 | `data/<ns>/oathbreaker/weapons/*.json` | 否：只增加池成员、权重、池标签；profile 仍读 DataMap |
| 代码注册 | `WeaponPool.register(WeaponDefinition.builder(...)...build())` | 是：可覆盖 profile、附带 HitEffect |
| 自定义 Item | 实现 `WeaponHitProvider` | 是：物品自身返回 HitEffect，适合继承第三方武器 |

解析优先级：代码定义 > JSON 池条目 > DataMap `weapon_profile`。

JSON 示例（不改武器行为）：

```json
{
  "item": "minecraft:bow",
  "weight": 10,
  "pool_tags": ["ranged", "starter"]
}
```

代码示例（附加命中效果 + 覆盖伤害段）：

```java
WeaponPool.register(WeaponDefinition.builder(Oathbreaker.id("my_blade"))
        .item(ResourceLocation.fromNamespaceAndPath("my_mod", "blade"))
        .profile(new WeaponProfile("melee",
                new DamageProfile(List.of(
                        new DamageComponent(DamageCategory.PHYSICAL, 0.7),
                        new DamageComponent(DamageCategory.MAGIC, 0.3))),
                Set.of(), Set.of(), 1.0))
        .hitEffect(context -> context.target().addEffect(new MobEffectInstance(MobEffects.WEAKNESS, 100)))
        .build());
```

按权重抽取：`WeaponPool.roll(random, definition -> definition.poolTags().contains("starter"))`。

`/oathbreaker pool` 可查看当前池条目数；`/oathbreaker profile` 会显示手持武器的池 ID、伤害构成与命中效果类名。
