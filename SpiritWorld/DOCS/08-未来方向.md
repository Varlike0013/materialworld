# 未来方向

## 1. 愿景

Spirit World 的下一阶段目标不是继续堆叠技能数量，而是把已经形成的闭环打磨成稳定、可读、可扩展的系统：

> 精神力 → 灵视成长 → 技能装配 → 魔力网络 → 口袋维度

围绕这条主线，优先解决正确性与状态一致性，其次提升多人/长期运行体验，最后再扩展内容深度。

## 2. 规划原则

1. **正确性优先于内容量**：先修复 `07-已知问题与演进建议.md` 中的 P0/P1 项。
2. **服务端权威不变**：任何新玩法继续沿用 capability + payload + 客户端镜像的架构。
3. **少改依赖库**：优先在 SpiritWorld 侧适配 AetherUI/MaterialWorld，避免把项目特有逻辑塞进公共库。
4. **数据集中维护**：技能数值继续集中在 `SkillValues`，文案继续集中在 `ModLanguageProvider`。
5. **每个阶段都要可验收**：功能完成必须伴随可复现的手动测试或自动化检查。

## 3. 路线图

> 阶段一、阶段二均已完成，并通过 `compileJava`、`runData`、`build` 验证。下表中的“具体内容/验收标准”作为已实现功能的变更记录与回归测试依据保留。

### 阶段一：稳定性与一致性（v1.0.x，P0/P1，已完成）

| 目标 | 已实现内容 | 回归验收方式 |
|---|---|---|
| 中继器 tier 不丢失 | 修复 `ManaRelayBlock.codec()`，按注册实例或方块状态恢复 tier | 保存/读取后三档节点类型、子节点上限、效率均正确 |
| 客户端缓存干净 | 补全 `ClientSpiritData.reset()` 的 `baseMaxSpirit`、`scanRange`、`scanOres` | 跨存档切换首帧无旧档数据 |
| 口袋维度扩建闭环 | 在 `PocketDimensionManager.tickTasks` 中真正推进 `BoundaryTask` | 技能升级后边界实际生成，尺寸与描述一致 |
| 访客请求可靠 | 改用 UUID/SavedData，增加统一过期清理 | 重启、改名、超时场景行为可解释且不串号 |
| 配置默认值统一 | `Config.POCKET_Y_OFFSET` 只保留一个默认值来源 | 全新配置下口袋维度 Y 坐标符合 spec |

### 阶段二：魔力网络可观测性（v1.1，已完成）

| 目标 | 具体内容 | 验收标准 |
|---|---|---|
| 网络树可视化增强 | 在 `SpiritCoreNetworkScreen` 中展示段效率、断链原因、离线影子产量 | 玩家能定位“为什么这个聚集器效率低” |
| 网络诊断命令 | 增加 `/spiritworld network diagnose`，输出节点数、断链数、效率分布 | 服务器日志或客户端反馈可直接用于排错 |
| 断链恢复策略 | 给孤儿节点增加有限次重试与冷却，避免每 tick 全图扫描 | 大网络下 tick 开销可测量且不随节点数指数增长 |
| 离线收益边界 | 明确离线影子收益上限、衰减规则并在 GUI 中说明 | 不会出现无限累积或上线瞬间爆仓 |

> 阶段二已实现：网络 GUI 现展示全部中继/聚集器的段效率、总效率、断链原因、子节点数与离线收益；新增 `/spiritworld network diagnose`；孤儿节点采用 100 tick 起始冷却 + 指数退避（上限 1600 tick）、每 20 tick 统一调度，拓扑变化时清空重试计数；离线收益限制为前 30 分钟全速、其后 90 分钟衰减至 50%、最多累计 2 小时。

### 阶段三：技能与装备深度（v1.2）

| 目标 | 具体内容 | 验收标准 |
|---|---|---|

| 装备成长反馈 | 魔力合金套装效果可视化，替换合金箭纹理，补充套装说明 | 套装激活有 HUD/粒子/提示反馈 |
| 技能重置体验 | 完善 `SkillRefundHelper` 的 UI 入口与退款预览 | 玩家可预览退款且不破坏灵视等级一致性 |
| 数值平衡 | 用 `SkillValues` 统一调参，增加数值快照测试 | 关键技能升级曲线稳定，不出现冷却归零/上限溢出 |

### 阶段四：口袋维度内容化（v1.3）

| 目标 | 具体内容 | 验收标准 |
|---|---|---|
| 领地升级可见 | 边界、平台、光照随等级变化有明确视觉反馈 | 升级前后对比明显，且无残留旧边界 |
| 访客权限 | 增加访问期限、单次进入、信任名单等轻量权限 | 主人可控制访客行为，请求不会串号 |

| 死亡与返回规则 | 明确死亡、掉线、改名后的领地坐标与返回点处理 | 与 `PlayerSpirit` 持久化规则一致 |

### 阶段五：工程化与生态（v2.0）

| 目标 | 具体内容 | 验收标准 |
|---|---|---|
| 自动化测试 | 覆盖灵视等级公式、段效率曲线、退款一致性、配置默认值 | `gradlew test` 在 CI 中通过 |
| 数据生成校验 | 对中英文 key、占位符、配方引用做生成后检查 | `runData` 后可自动报告缺失或多余条目 |
| 附属 Mod API | 抽象魔力类型/网络节点扩展点，减少对具体类的硬依赖 | 第三方可用少量代码实现新节点或新魔力类型 |
| 文档同步机制 | 类/函数索引、网络包表、HUD 坐标表随代码变更更新 | PR 模板包含文档检查项 |

## 4. 明确不做的事

- 不把 MaterialWorld 或 AetherUI 的公共 API 改成 SpiritWorld 专用行为。
- 不为单一技能新增独立网络包；优先复用现有 payload 或合批同步。
- 不在客户端保存可持久化权威数据；客户端始终是镜像。
- 不把运行时魔力合成表迁移到 datagen，除非同步改造核心读取逻辑。

## 5. 风险与依赖

| 风险 | 说明 | 缓解方式 |
|---|---|---|
| AetherUI API 变更 | HUD、世界标记依赖 AetherUI 1.1.1 | 将适配集中在 `client/aether` 与 `SpiritScanRenderer`，升级时先跑 UI 冒烟测试 |
| MaterialWorld 版本对齐 | 创造标签与附属 API 由 MaterialWorld 提供 | 在 `gradle.properties` 固定版本，升级先验证创造标签与依赖解析 |
| 口袋维度异步生成 | 大半径扩建可能造成卡顿或半生成状态 | 分帧预算、状态持久化、失败重试与日志 |
| 数值膨胀 | 技能越多越难保持冷却/上限稳定 | `SkillValues` 集中管理并加边界测试 |

## 6. 近期建议顺序

1. 修复 `ManaRelayBlock.codec()` 与 `ClientSpiritData.reset()`（P0）。
2. 完成口袋维度边界任务与访客请求持久化（P1）。
3. 增加网络诊断信息与 `%占位符` 语言校验脚本（P1/P2）。
4. 再启动装备外观、技能深度与 v2.0 API 抽象。

具体缺陷明细见 `07-已知问题与演进建议.md`；玩法与数据流基线见 `02-核心玩法设计.md`。
