# 网络与数据同步设计

## 1. 设计原则

- **服务端权威**：所有可持久化状态、消耗校验、拓扑计算都在服务端完成。
- **客户端镜像**：客户端只缓存展示所需数据，通过 payload 增量或全量刷新。
- **显式校验**：涉及消耗、装配、距离的操作在服务端再次校验，不信任客户端参数。

## 2. Payload 清单

注册入口：`network/NetworkHandler.register(RegisterPayloadHandlersEvent)`。

| 方向 | 类名 | 作用 |
|---|---|---|
| S→C | `ClientboundSyncSpiritPacket` | 全量同步精神力、上限、灵视点/碎片、技能等级、技能栏、被动、扫描配置 |
| S→C | `ClientboundScanResultPacket` | 返回扫描到的矿物簇坐标、图标物品、数量与持续时间 |
| S→C | `ClientboundNetworkTreePacket` | 返回完整网络树（核心/中继/聚集器）、总效率/段效率/断链原因/离线收益/子节点数与抽取明细 |
| C→S | `ServerboundRequestSyncPacket` | 请求一次全量同步 |
| C→S | `ServerboundLearnSkillPacket` | 学习/升级技能 |
| C→S | `ServerboundSetLoadoutPacket` | 装配或清空指定槽位 |
| C→S | `ServerboundSetSelectedSlotPacket` | 切换当前选中技能槽 |
| C→S | `ServerboundTogglePassivePacket` | 开关可切换被动 |
| C→S | `ServerboundUseSkillPacket` | 使用当前装配技能（无参数） |
| C→S | `ServerboundSetScanConfigPacket` | 设置扫描范围与目标矿物 |
| C→S | `ServerboundRequestNetworkDataPacket` | 请求核心网络拓扑数据 |
| C→S | `ServerboundCoreActionPacket` | 核心 UI 操作（目标数量调整等） |

## 3. 同步时机

| 场景 | 触发者 | 行为 |
|---|---|---|
| 玩家登录 | `SpiritGameHandler.onPlayerLogin` | 从 NBT 恢复 → `NetworkHandler.syncTo` → 立即落盘 |
| 周期同步 | `SpiritTickHandler` | 数据 dirty 且到达 `Config.syncInterval` 时同步 |
| 客户端请求 | `ServerboundRequestSyncPacket` | 服务端立即 `syncTo` |
| 技能操作后 | 学习/装配/切换/扫描配置等 payload | 写 `PlayerSpirit` 后立即 `syncTo`，关键操作同时落盘 |
| 退出/换世界 | `ClientSpiritData.reset()` | 清空客户端镜像，避免跨存档污染 |

`NetworkHandler.syncTo(ServerPlayer)` 从 capability 读取 12 项字段组装 `ClientboundSyncSpiritPacket`，是唯一的玩家数据全量出口。

## 4. 魔力网络数据

`network` 包除 payload 外还包含拓扑支撑类：

| 类 | 职责 |
|---|---|
| `NetworkManager` | 全局节点表 `ALL_NODES` 与离线影子 `SHADOW_DATA`；`registerNode/unregisterNode/updateShadowData/getShadowData/tickRelinks` |
| `INetworkNode` | 节点统一接口：类型、效率、父/子节点、断链原因、延迟重连 |
| `AbstractNetworkNodeBlockEntity` | 公共节点实现：择优父节点、级联效率、断链原因、NBT 持久化 parent/efficiency/linkReason/relinkAttempts |
| `EfficiencyCalculator` | 各类型最大范围、段效率曲线（35 格无损，其后线性衰减至 10%） |
| `OfflineCollectorData` | 离线影子：前 30 分钟全速，其后 90 分钟线性衰减至 50%，最多累计 2 小时并封顶容量 |
| `NetworkEvents` | 服务端 tick 中每 20 tick 调度孤儿节点重连 |

节点变化采用“放置即注册、读档即重注册、拆除即断链”的策略：所有节点在 `loadAdditional` 时重新登记，核心在 `onPlace` 注册并在 `onRemove` 注销/断链；`NetworkManager.registerNode` 在拓扑变化时清空所有节点的重连次数与冷却，避免新核心/中继放置后旧节点因 3 次上限永久失联。失败重连改为指数退避（100 → 1600 tick 上限），不再有永久停止阈值。`NetworkEvents` 每 20 tick 统一调度重连。客户端只有在打开核心网络界面时通过 `ServerboundRequestNetworkDataPacket` 请求一次快照；快照现在包含所有中继器的总效率、段效率、断链原因、离线收益与子节点数。

### 诊断命令

`/spiritworld network diagnose` 汇总所有维度的节点数、断链数以及效率分布（<50%、50-80%、>80%），同时写入服务端日志，便于在不打开 GUI 的情况下排错。

## 5. 校验规则

- 技能学习：等级上限、前置技能、灵视等级、可用灵视点四项校验。
- 装配：技能必须已学习且 `node.isEquippable()`。
- 核心 UI 操作：玩家与核心距离不超过 8 格。
- 扫描配置：范围必须在 `SkillValues.SCAN_RANGE` 允许区间并按步长对齐，矿物集合受服务端白名单约束。
- 口袋维度：传送扣 20 精神力，活跃名额与领地分配由服务端 SavedData 控制。

## 6. 新增 Payload 的步骤

1. 在 `network` 包创建 `record XxxPacket(...)` 实现 `CustomPacketPayload`，并写 `Type<T>`。
2. 在包内实现 `handle(IPayloadContext)`，服务端逻辑必须重新校验关键参数。
3. 在 `NetworkHandler.register` 中注册 `addClientbound` 或 `addServerbound`。
4. 若影响玩家展示数据，扩展 `ClientboundSyncSpiritPacket` 字段并同步 `ClientSpiritData.update(...)` 与 `reset()`。
5. 在 `06-类与函数索引.md` 与本文档表格中补充记录。
