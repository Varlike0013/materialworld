## 2. 缺陷清单

### P0-1 中继器 `codec()` 丢失 tier

- **位置**：`block/ManaRelayBlock.java:26-27`
- **现象**：`protected MapCodec<? extends BaseEntityBlock> codec()` 固定返回 `simpleCodec(props -> new ManaRelayBlock(props, 1))`。
- **根因**：三档中继器实际由 `ModBlocks` 用不同 tier 构造，但反序列化路径没有恢复 tier，源码注释明确标注为占位。
- **影响**：2/3 档中继器在某些加载、放置或结构反序列化场景下会退化为 1 档，导致 `getNodeType()`、`getMaxChildren()` 与中继范围全部错误，魔力网络拓扑计算结果不可信。
- **修复方案**：让 codec 从方块状态或注册实例中读取 tier；或为三档分别注册独立 Block 类并在各自 `codec()` 中固定对应 tier。
- **验证**：分别放置三档中继，保存/读取世界后检查 `getTier()`、子节点上限与 `NetworkManager` 中的节点类型。

### P0-2 `ClientSpiritData.reset()` 未清空全部客户端缓存

- **位置**：`client/ClientSpiritData.java:76-86`
- **现象**：`reset()` 清空了精神力、灵视点、技能等级、技能栏与被动，但没有重置 `baseMaxSpirit`、`scanRange`、`scanOres`。
- **根因**：后续 `update(...)` 新增了这三个字段，`reset()` 未同步维护。
- **影响**：退出世界进入另一个存档时，HUD 可能短暂显示上一个存档的“被扣上限”，扫描配置界面可能保留上一个存档的范围与目标矿物，直到服务端下一次同步才纠正。
- **修复方案**：在 `reset()` 中加入 `baseMaxSpirit = 0L; scanRange = 8; scanOres = new HashSet<>();`。
- **验证**：在两个不同存档间切换，确认进入新存档首帧的蓝条与扫描配置不残留旧数据。

### P1-1 口袋维度边界生成任务未执行

- **位置**：`world/PocketDimensionManager.java:103-120`
- **现象**：`queueBoundaryTask(...)` 能把 `BoundaryTask` 加入静态列表，但 `tickTasks(Level level)` 只取队首任务，方法体没有实际生成逻辑，注释写着“放到稍后的 Handler 中执行”。
- **影响**：升级口袋维度技能后，安全平台可能生成，但边界扩建不会完成；玩家看到的领地尺寸与技能描述不一致。
- **修复方案**：在 `tickTasks` 中按每 tick 预算推进 `PocketGenerationTask`，完成后从队列移除；确保任务在服务端线程执行并限额避免卡顿。
- **验证**：将口袋维度升到 2 级，进入维度后观察边界是否按 `SkillValues.POCKET_SIZE_XZ/Y` 扩建完成。

### P1-2 访客请求未持久化且依赖玩家名匹配

- **位置**：`world/VisitRequestManager.java:13-80`
- **现象**：`REQUESTS` 是静态内存 `Map<UUID, Map<UUID, Long>>`，重启即失效；`sendRequest` 生成的接受/拒绝命令使用 `sender.getName().getString()`，`acceptRequest` / `denyRequest` 再按名字反查 UUID。
- **影响**：服务器重启后所有待处理请求丢失；改名、重登、同名玩家都可能导致请求无法接受或被错误匹配。清理只在 `sendRequest` / `acceptRequest` 时针对单个 target 调用，离线目标的数据不会自动回收。
- **修复方案**：改为服务端 SavedData 或至少按 UUID 生成命令参数；增加统一 tick 清理过期请求；不再以显示名作为身份标识。
- **验证**：发送访问请求后重启服务器，确认请求状态符合预期；改名玩家的请求仍能被正确接受或拒绝。

### P1-3 配置 `pocketDimensionYOffset` 默认值不一致

- **位置**：`Config.java:53-54` 与 `Config.java:69`
- **现象**：`ModConfigSpec` 默认值为 `200`，但静态字段 `pocketDimensionYOffset` 初值为 `100`。
- **影响**：若某些代码路径在 `Config.loadValues()` 之前读取该字段，口袋维度 Y 坐标会与配置默认值不一致，表现为同一配置下不同启动阶段落点不同。
- **修复方案**：把静态字段初值统一为 `200`，或统一从 spec 读取，避免硬编码第二份默认值。
- **验证**：删除配置文件后首次启动，进入口袋维度，确认 Y 坐标与 spec 默认值一致。

### P1-4 外壳遍历实现被简化

- **位置**：`world/PocketGenerationTask.java:92-103`
- **现象**：`createOldBoundaryIterator()` 注释说明“简化为遍历整个外壳”，通过 `OuterShellIterator` 过滤 `BoundingBox`。
- **影响**：大半径领地升级时，旧边界清理可能遍历大量非边界坐标，增加生成任务开销；若 `OuterShellIterator` 的边界判断与 `BoundingBox` 端点处理不一致，可能漏掉/重复处理角落方块。
- **修复方案**：显式按六个面生成坐标，避免全包围盒扫描；为 `OuterShellIterator` 增加单元测试覆盖角、边、面。
- **验证**：升级到最大口袋尺寸，记录生成任务耗时与边界完整性。

### P2-1 合金箭渲染使用原版纹理

- **位置**：`client/ManaAlloyArrowRenderer.java:8-16`
- **现象**：`TEXTURE` 指向原版 `textures/entity/projectiles/arrow.png`，注释说明后续替换为紫色光效箭。
- **影响**：魔力合金箭与普通箭视觉无差异，装备成长反馈弱。
- **修复方案**：添加专属纹理并覆盖 `getTextureLocation`，必要时叠加轻微发光层。
- **验证**：第一人称与第三人称下射击，确认箭体外观与普通箭明显区分。

### P2-2 技能学习失败提示为临时实现

- **位置**：`client/skill/SkillTreeScreen.java:59-60`
- **现象**：`feedback` 字段注释为“临时提示”，目前是底部居中文本约 2.5 秒。
- **影响**：功能可用，但缺少与技能树视觉风格一致的提示动效/音效，失败原因不够醒目。
- **修复方案**：改为可复用的通知组件，支持颜色分级、渐隐与定位到目标技能节点。
- **验证**：分别触发满级、前置未学、灵视不足、点数不足四类失败，确认提示清晰且互不覆盖。

### P2-3 已废弃配置项仍出现在配置界面

- **位置**：`ClientConfig.java:14-37`
- **现象**：`spiritBarYOffset`、`hudPassiveMaxRows/PerRow/IconSize` 仍定义在 spec 中，但 HUD 已交由 AetherUI 布局，代码不再读取。
- **影响**：用户修改这些选项看不到效果，增加支持成本。
- **修复方案**：移除废弃项；若担心旧配置文件报错，可保留字段但加 `.comment("废弃...")` 并隐藏或标记 deprecated。
- **验证**：打开客户端配置界面，确认只剩下有效选项。

## 3. 设计性说明（非缺陷）

- `SkillValues` 多个数组的索引 0 是等级对齐占位；0 级表示未学习，不参与计算。
- `PlayerSpirit.skillCooldownEnds`、`flightCostAccum`、`flightGliding`、`maxSpiritModifiers` 不序列化、不跨死亡复制，是有意设计。
- 多个 Screen 的 `renderBackground(...)` 为空实现，是为了避免原版半透明黑底与模糊覆盖自定义背景，不属于遗漏。
- 魔力核心合成表 `ManaCraftingRecipes` 是运行时数据，不应直接改为 datagen JSON，除非同时改造核心读取逻辑。
