# 核心玩法设计

## 1. 玩家资源模型

服务端真源为 `capability/PlayerSpirit`，客户端镜像为 `client/ClientSpiritData`。

| 字段 | 含义 | 关键方法 |
|---|---|---|
| `spirit` / `maxSpirit` / `baseMaxSpirit` | 当前精神力、有效上限、基础上限 | `getEffectiveMaxSpirit()`、`consumeSpirit(long)`、`addSpiritWithFraction(double)` |
| `totalSpentVisionPoints` | 累计消耗的灵视点，用于推导灵视等级 | `getVisionLevel()` |
| `availableVisionPoints` | 可消费灵视点 | `consumeVisionPoints(long)` |
| `visionFragments` | 灵视碎片，100 碎片兑换 1 点 | `addVisionFragments(long)` |
| `learnedSkills` | 技能 ID → 等级 | `setSkillLevel(...)` |
| `loadout` / `selectedSlot` / `activePassives` | 6 格技能栏、当前槽、已开启被动 | `setLoadoutSlot(...)`、`isPassiveActive(...)` |
| `pocketPosition` / `returnPoint` | 口袋维度内坐标与主世界返回点 | `setPocketPosition(...)`、`setReturnPoint(...)` |

灵视等级公式（`PlayerSpirit.getVisionLevel()`）：

\[
\text{level} = \max \{ n \mid \frac{n(n+1)}{2} \times 10 \le \text{totalSpentVisionPoints} \}
\]

上限 `MAX_VISION_LEVEL = 10`。等级不是直接存储字段，而是由累计消耗动态推导，避免退款/重算导致状态不一致。

## 2. 精神力与灵视点的流转

1. `SpiritTickHandler` 按 `Config.spiritRegenInterval` 恢复基础精神力，并叠加精神洪流、精神源泉等被动。
2. 技能学习、飞行、护盾、扫描、口袋维度传送均通过 `consumeSpirit` 扣费。
3. 击杀生物由 `VisionFragmentEvents` 按生物类型倍率产出灵视碎片；每 100 碎片转 1 灵视点。
4. 学习技能时 `consumeVisionPoints(cost)` 并 `addSpentVisionPoints(cost)`，同时累计消耗提升灵视等级。
5. `SkillRefundHelper` 负责技能重置时的退款，退款同时回退累计消耗以保持等级一致。

## 3. 魔力网络

### 3.1 节点类型

| 节点 | 角色 | 子节点上限 | 最大范围 |
|---|---|---|---|
| `CORE` | 精神核心，网络根，持有魔力池与容量 | — | 100 |
| `RELAY_1/2/3` | 魔力中继，逐级扩展范围与带载 | 4 / 8 / 16 | 100 / 200 / 300 |
| `COLLECTOR` | 聚集器，产魔源，只能作叶子 | 0 | 0 |

### 3.2 拓扑建立

1. 放置中继/聚集器 → `onPlace` → `NetworkManager.registerNode(level,pos,type)`。
2. `AbstractNetworkNodeBlockEntity.findParent()` 遍历全局节点，跳过聚集器与满载节点，使用 `EfficiencyCalculator.calculateSegmentEfficiency` 计算段效率。
3. 节点总效率 = 父节点效率 × 段效率；段的无损距离为 35 格，之后线性衰减到 10%，超过最大范围返回 -1 并拒绝连接。
4. 核心通过 `registerCollector(pos,eff)` 登记聚集器；`rebuildNetwork()` 重新计算全网。
5. 拆除节点 → `disconnectChildren()` + `unregisterNode()`，孤儿节点下次 tick 重找父节点。

### 3.3 存储与抽取

- `SpiritCoreBlockEntity` 维护 `Map<ManaType, Long>` 魔力池。
- `recalculateCapacity()` 用 BFS 统计相邻魔力方块，按距离加权得到容量加成。
- `pullMana()` 从聚集器抽取，实际入库 = 抽取量 × 节点效率。
- `OfflineCollectorData` 作为离线影子数据：前 30 分钟按 100% 速度累计，其后 90 分钟线性衰减至 50%，最多累计 2 小时并封顶容量。
- 孤儿节点断开后进入 100 tick 冷却并按失败次数指数退避（上限 1600 tick），由 `NetworkEvents` 每 20 tick 统一调度；拓扑变化会清空重连次数，避免永久失联。`ClientboundNetworkTreePacket` 会把断链原因、段效率与离线收益带到 GUI。
- 魔力类型由 `ManaEnvironmentDetector.detect(level,pos)` 根据周边环境判定（火/水/风/土/精神/无）。

### 3.4 合成

- **运行时配方**：`skill/ManaCraftingRecipes` 维护 12 条核心配方（魔力砖、各种矿物、水晶、合金等），由 `SpiritCoreBlockEntity` 解析消耗与产出。
- **原版配方**：`datagen/ModRecipeProvider` 生成普通合成/熔炼配方，属于数据包资源。

## 4. 技能系统

- `ModSkills` 定义全部技能 ID，`SkillNode` 定义单节点配置：等级上限、前置、灵视等级要求、消耗、是否可装配/可切换/常驻。
- `SkillTree` 是全局节点表；`SkillValues` 集中放置所有数值函数，便于平衡。
- 学习流程：GUI → `ServerboundLearnSkillPacket` → 服务端校验 → 扣点 → 写 `PlayerSpirit` → 同步 + 落盘。
- 装配流程：`ServerboundSetLoadoutPacket` / `SetSelectedSlotPacket` / `TogglePassivePacket`。
- 使用流程：`ServerboundUseSkillPacket` → 取当前装配技能 → 冷却检查 → 分派到具体 Handler（工具、修复、扫描、飞行、口袋维度等）。
- `SkillBonusCalculator`、`SpiritMaxCalculator`、`SkillCooldownCalculator` 统一提供被动加成与冷却倍率。

## 5. 口袋维度

1. 使用技能后 `PocketDimensionHandler.toggleDimension` 切换维度。
2. `PocketDimensionManager.getOrAssignCenter(UUID,server)` 通过 `PocketDimensionData` SavedData 分配中心；中心按 `SPACING=256` 螺旋排布，受活跃名额限制。
3. `PocketChunkLoader` 强加载玩家领地区块；技能等级高于已生成等级时入队 `PocketGenerationTask` 异步扩建。
4. 传送进入时生成 9×9 安全站台；退出时记录 `pocketPosition` 并返回 `returnPoint`。
5. 访客通过 `/spiritworld visit <player>` 发起请求，请求持久化在 `PocketDimensionData` 中、60 秒后过期，接受/拒绝命令使用访客 UUID；接受后 `PocketDimensionHandler.teleportVisitor` 传送。

## 6. 配置与数值

COMMON 配置类为 `Config`（不是 `ModConfig.java`），关键项：精神力恢复量/间隔、默认上限、同步间隔、瓶装精神恢复量、登录/死亡是否清空、EMC 转化成本、飞行消耗倍率、扫描图标上限、口袋维度活跃人数与 Y 偏移。

CLIENT 配置类为 `ClientConfig`，有效项为 `showSpiritBar`、`showSpiritText`；其余 HUD 位置相关字段已废弃，由 AetherUI 统一布局。
